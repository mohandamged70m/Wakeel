## 0. What this demo actually is (read before filming)

- **It is a front-end demo.** All data comes from `frontend/src/lib/mock.seed.ts` (6 orders, 5 conversations, 6 customers, 7-day order counts). `frontend/src/lib/demo.ts` adapts that seed into the API types; `frontend/src/lib/api.ts` falls back to it automatically when the backend is unreachable.
- **No backend is required for filming.** `npm run dev` starts NestJS on 3001, but with empty env vars it has no Supabase/OpenAI/Evolution/Redis and will not serve real data. The dashboard still renders fully because the proxy (`frontend/src/lib/supabase/proxy.ts`) lets requests through when `NEXT_PUBLIC_SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_ANON_KEY` are empty.
- **AI replies shown in the Inbox are pre-baked strings** in `demo.ts` (e.g. the 155 EGP shawarma+humus quote). They illustrate the *shape* of a DB-priced reply; they are not generated by an LLM during filming. Do not claim in the pitch that the reply was generated live.
- **The WhatsApp status card in Settings shows "connected"** with a seed number (+20 100 000 0000). That is demo state, not a real paired number.
- **Voice notes render as text** via a transcript card in the message thread (seed: Sara Ali's "three falafel wraps, maadi address"). This demonstrates the voice→text feature visually; real STT (Whisper/OpenAI) is NOT verified.

**Filming rule:** never say "this is live" or "connected to a real number." Say "this is how it works" / "هكذا يعمل النظام."

## 1. Setup (run locally, ~3 minutes)

Prereqs: Node 20+, npm. No Docker, no env secrets.

1. Open a terminal in `D:\projects\Agent for whatsapp`.
2. `npm run setup` (installs backend + frontend deps). Skip if already done.
3. `copy backend\.env.example backend\.env` and `copy frontend\.env.example frontend\.env.local`. **Leave all secrets empty** — that is what enables demo mode (see `frontend/src/lib/supabase/proxy.ts`: empty Supabase URL/key = no auth redirect = dashboard renders with seed data).
4. Start: `npm run dev` (concurrently backend 3001 + frontend 3000) — or double-click `scripts\start-all.bat` on Windows. Wait for `Ready` on port 3000.
5. Open `http://localhost:3000` in Chrome. Because Supabase env is empty, `/dashboard` renders without login.
6. Verify the four screens load with data before recording: `/dashboard` (Overview), `/dashboard/inbox`, `/dashboard/orders`, `/dashboard/settings`.
7. Toggle dark mode and switch `dir="rtl"` (Arabic) once to confirm nothing breaks on camera. If it breaks, film in LTR Arabic-text mode instead and note it.

**Recording setup:** 1080p, browser at ~1280×800 (desktop) or 390×844 (mobile emulation for the "works on phone" beat). Capture system audio off; record voiceover separately in Arabic.

## 4. First paying customer — release checklist (when someone says yes)

Only run this when Mohand has a paying customer. Order matters: Supabase → Backend → Frontend. Source: `Docs/RELEASE-CHECKLIST.md`.

### 4.1 Provision (cost ~$0 on free tiers, ~$25–30/mo at first paid customer)
- Supabase free project (DB/Auth/Realtime/RLS) — global, works from Egypt.
- Upstash free Redis (serverless, BullMQ-compatible) — global.
- Vercel Hobby for the Next.js frontend — global, free.
- Backend host: Oracle Cloud Always Free (ARM VM, 2 vCPU, 12–24GB RAM, $0 forever, needs credit card for verification only) — recommended for always-on NestJS + BullMQ worker + Evolution. Alternative: laptop + Cloudflare Tunnel for $0 with no card (PC must stay on).
- Evolution API on Railway (Docker) or on the same Oracle VM — needs persistent disk for QR pairing state.

### 4.2 Deploy order
1. **Supabase:** create project → apply `infra/supabase/migrations/0001_init.sql` → verify RLS on all 14 tables (`select tablename, rowsecurity from pg_tables where schemaname='public'`) → seed one org + owner user.
2. **Backend:** set all 9 env vars from `backend/.env.example` on the host → `npm run build` → start → `curl /health` returns 200 → confirm DB connectivity.
3. **Frontend (Vercel):** set `NEXT_PUBLIC_API_URL` to the live backend URL (not `localhost`) → `NEXT_PUBLIC_SUPABASE_URL` + `NEXT_PUBLIC_SUPABASE_ANON_KEY` from the project → build passes → `/login` → `/dashboard` flow works.
4. **Evolution:** start instance → pair one real WhatsApp number via QR → set webhook to `https://<backend>/webhooks/whatsapp` with `EVOLUTION_WEBHOOK_TOKEN` → send a test message → confirm it lands in the Inbox without refresh.

### 4.3 Gate (must all pass before handing to a customer)
- [ ] `npm run lint` 0 errors; `npm run build` passes both apps.
- [ ] Typecheck (`tsc --noEmit`) clean, no `any` in controllers/API clients.
- [ ] No secrets in git history (grep).
- [ ] RLS cross-org test: 0 leaks (`Docs/RLS-CROSS-ORG.md`).
- [ ] Price-accuracy eval: 20/20, 0 wrong prices (`Docs/EVAL-PRICE-ACCURACY.md`).
- [ ] E2E order flow: HP-1 A1–A10 pass 3 consecutive runs; FM-1–FM-10 pass once (`Docs/E2E-ORDER-FLOW.md`).
- [ ] Visual audit: all 8 screens at 360/768/1280/1440, light+dark, LTR+RTL (`Docs/VISUAL-AUDIT.md`).
- [ ] Owner can disable auto-reply; agent stops within one message (FM-10).
- [ ] Urgent keyword → owner notification within 5s (case 13).
- [ ] Business hours away-message works (FM-8).
- [ ] No auto-confirm without owner approval (FM-4).
- [ ] Customer confirmation sent on approve (A9).
- [ ] Sentry + PostHog receiving events (or documented waiver).
- [ ] Rollback plan acknowledged by Mohand.

### 4.4 Rollback
- **Code:** `git revert` to `25c8382` (Phase 1 baseline) if anything breaks; Vercel instant rollback via dashboard (keep last 3 deployments); Render/Railway redeploy previous commit.
- **DB:** Supabase PITR to timestamp before deploy. Migrations are additive so far (no destructive changes); every new migration needs a `down.sql`.
- **WhatsApp session:** if Evolution breaks during deploy, re-scan QR via dashboard; messages are persisted, no data loss.
- **Feature flags:** auto-reply defaults OFF for new orgs; existing orgs keep their setting on rollback.
- **Rollback triggers:** any cross-org data leak, any wrong price in prod, webhook 5xx rate > 1%, or owner-notification failure > 5 min.

### 4.5 Post-release (first 24h)
- Smoke test within 30 min of deploy: real WhatsApp message → reply → place order → approve → confirm.
- Monitor Sentry for new error types (target 0).
- Monitor Evolution session state (target: connected).
- PostHog: at least one conversation + one order event if traffic exists.
- Message Mohand with any friction within 24h.
