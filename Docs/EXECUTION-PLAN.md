## 1. What "AI slop" means here (concrete tells we are removing)

Frontend tells currently present:
- `app/page.tsx` is still the untouched `create-next-app` template ("To get started, edit page.tsx").
- `layout.tsx` metadata is "Create Next App" / "Generated by create next app".
- Sidebar icons are emoji (📊 💬 🎯 🧾 👥 📚 ⚙️) — inconsistent, OS-rendered, screams scaffold.
- No design tokens: colors/spacing/radius hardcoded inline per component; no CSS variables beyond background/foreground.
- No component kit: `DASHBOARD.md` §4 lists 15 components (KpiCard, StatusPill, …) — **none exist**. Everything is inlined in page files.
- Translation bugs: `takeOver: " takeover"` (leading space), `returning: "Returning"` untranslated in Arabic, `askedForHuman` tag missing from `ChatTag` union (cast to `any`).
- Mock data only; no real data layer, no loading/empty/error states.
- Dark mode is `prefers-color-scheme` only — no manual toggle that persists.
- RTL set via `dir` but components mix `border-e`/`border-r` inconsistently; not audited.
- No keyboard shortcuts, no visible focus, no `prefers-reduced-motion`, no a11y labels on charts.

Backend tells currently present:
- Only `WhatsAppModule` exists. No auth, organizations, users, conversations, messages, menu, orders, customers, automations, analytics, notifications, ai.
- `QueueService.process` is a placeholder echo ("Thanks! We received…").
- No Supabase client, no RLS, no validation pipe, no error filter, no OpenAPI, no health checks beyond WhatsApp.
- Webhook returns 200 but never persists; idempotency is documented but not implemented.
- No tests beyond the Nest scaffold spec.

## 5. Anti-slop guardrails (apply to every PR)

1. **No emojis as icons.** Use lucide-react. (CI: grep fails build if emoji in `src/`.)
2. **No default template leftovers.** No "create-next-app", no "To get started, edit".
3. **No inline magic colors.** All colors via tokens; raw hex only in `globals.css`.
4. **Every list/detail has 3 states:** loading skeleton, empty state, error state.
5. **No mock data in runtime paths.** Mocks only in `lib/mock.seed.ts` (demo seeding) or tests.
6. **Translations complete.** No key missing in AR; no leading/trailing spaces; `t()` returns never-undefined.
7. **Accessibility baseline:** visible focus ring, keyboard nav on lists, `aria-label` on icon buttons, `prefers-reduced-motion` respected, contrast ≥4.5:1.
8. **RTL audited.** Logical properties only; screenshot review in AR before merge.
9. **Backend: no `any` in controller signatures.** Zod schemas at boundaries; OpenAPI types generated.
10. **Prices never from LLM.** System prompt + tool-only enforcement + eval gate.

## 6. API contract (Pixel + Lin agree before Phase 3/4)

Base: `NEXT_PUBLIC_API_URL` (default `http://localhost:3001`). Auth: `Authorization: Bearer <supabase jwt>`.

| Method | Path | Returns |
|---|---|---|
| GET | `/conversations?status=&q=` | `{ items: Conversation[], nextCursor }` |
| GET | `/conversations/:id/messages` | `{ items: Message[] }` |
| POST | `/conversations/:id/takeover` | `{ status: 'human' }` |
| POST | `/conversations/:id/return-to-bot` | `{ status: 'bot' }` |
| GET | `/orders?status=&cursor=` | `{ items: Order[] }` |
| GET | `/orders/:id` | `OrderDetail` (items with snapshots, approvals, payment) |
| POST | `/orders/:id/approve` | `Order` |
| POST | `/orders/:id/reject` | `Order` |
| POST | `/orders/:id/edit` | `Order` (body: items[]) |
| GET/POST/PUT/DELETE | `/menu/categories`, `/menu/items` | standard CRUD |
| GET | `/customers?cursor=` | `{ items: Customer[] }` |
| GET | `/customers/:id` | `CustomerDetail` |
| GET/PUT | `/automations` | `Automations` |
| GET | `/analytics/overview?range=` | `AnalyticsOverview` |
| GET | `/health/whatsapp` | `{ connected, state, lastSeen }` |
| POST | `/webhooks/whatsapp` | (Evolution delivery, server-to-server) |

Realtime: Supabase Realtime channels `conversations`, `orders` (org-scoped via RLS). Pixel subscribes; Lin publishes via DB writes.

## 7. Tradeoffs & decisions

- **Supabase cloud vs self-host Postgres:** use Supabase cloud free tier. No VPS money (per memory); simpler for portfolio demo; RLS built in. Self-host only if a client demands data residency.
- **Redis/BullMQ vs inline:** keep inline fallback for dev (user's machine is slow with Redis/Docker). BullMQ only when `REDIS_URL` set. Production path is BullMQ.
- **shadcn/ui vs hand-rolled kit:** use shadcn (Radix primitives → a11y for free) **but** customize tokens/spacing/typography so it does not look like default shadcn. This is the single biggest anti-slop lever.
- **AR-first vs bilingual:** recommend AR-first with EN fallback (open question #3 in PLAN.md). Persona prompt bilingual; menu names in both.
- **Evolution (unofficial) vs Meta:** keep Evolution for portfolio/demo; provider abstraction already in place (`whatsapp-provider.interface.ts`); Meta is a config swap later.
- **Payments:** do not block MVP. Stripe for SaaS billing later; Paymob/Fawry for order payments later.
